# StripchatRecorder Community Modules

[简体中文](README.md) | [English](README.en.md)

This repository is the **central index** for [StripchatRecorder](https://github.com/ChanTrail/StripchatRecorder) community post-processing modules.

---

## How it works

Two-level structure:

- **This repo** (central index): `registry.json` stores only a sequence number and repo URL per module.
- **Module maintainer repos**: Full module metadata (name, version, download URLs, sha256, etc.) lives in a `registry.json` at the root of each maintainer's own repo. Maintainers update it directly — **no PR to this repo needed**.

```
Central index registry.json        Module maintainer's registry.json
──────────────────────             ─────────────────────────────────
[                                  {
  { "id": "00000001",                "id": "my_module",
    "repo": "github.com/..." }  →    "latestVersion": "1.2.0",
]                                    "downloads": { ... },
                                     "sha256": { ... }
                                   }
```

## Submitting a new module (one-time)

1. **Create your own module repo** using the template in [`module-template/`](./module-template/).
2. **Add a `RELEASE_PAT` secret**: GitHub avatar → Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token (classic), check **repo** scope and generate, copy the token; then go to the module repo Settings → Secrets → Actions → New repository secret, set Name to `RELEASE_PAT` and paste the token into Secret.
3. **Only three things to change**:
   - `Cargo.toml`: change `name` (module ID) and `version`
   - `src/main.rs`: implement processing logic, update param definitions in `DESCRIBE`
   - `registry.json`: fill in `description` and `tags` (**only these two fields**; everything else is auto-generated by the Release workflow)
4. **Open one PR to this repo** and append one line to `registry.json`:

```json
{ "id": "00000NNN", "repo": "https://github.com/your-username/stripchat-pp-your-module" }
```

Take the current highest `id` + 1, zero-padded to 8 digits.

---

## Releasing a new version (fully self-managed, no further PR needed)

Bump `version` in `Cargo.toml` and push to main:

- CI automatically pushes the tag
- Release workflow automatically builds, computes sha256, updates `registry.json`, and creates a GitHub Release
- StripchatRecorder picks up the new version on the next refresh

---

## registry.json format

```json
[
  { "id": "00000001", "repo": "https://github.com/user/stripchat-pp-module" },
  { "id": "00000002", "repo": "https://github.com/user2/stripchat-pp-module2" }
]
```

| Field  | Description |
|--------|-------------|
| `id`   | 8-digit sequence number (starting from `00000001`, incrementing by submission order), used only for list ordering |
| `repo` | GitHub URL of the module maintainer's repository |

---

## Review criteria

- `repo` points to a valid public GitHub repository
- The repo root contains a correctly parseable `registry.json`
- No malicious code, no user data collection, no unnecessary external network requests
